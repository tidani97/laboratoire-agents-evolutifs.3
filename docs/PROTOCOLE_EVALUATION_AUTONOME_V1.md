CDI-TRADER — PROTOCOLE D’ÉVALUATION AUTONOME V1

1. Objectif

Évaluer les capacités réelles des agents CDI-TRADER sans accès aux positions, aux décisions ou à l’historique de trading personnel de son créateur.

2. Indépendance

• Aucune lecture des trades personnels.
• Aucune imitation des positions de l’utilisateur.
• Aucune transmission de ses habitudes de trading.
• Analyses fondées exclusivement sur les données de marché autorisées.
• Chaque agent conserve une identité et un historique de performance distincts.

3. Conditions expérimentales

Les agents seront évalués dans quatre environnements :

• Marché haussier.
• Marché baissier.
• Marché latéral.
• Marché fortement volatil.

Des événements supplémentaires seront introduits : retournements, pertes consécutives, données manquantes, données incohérentes et interruptions de flux.

4. Absence de fuite d’information

À chaque cycle :

1. Les agents reçoivent uniquement les informations disponibles à cet instant.
2. Ils formulent leurs propositions.
3. Le décideur unique valide, refuse ou demande l’attente.
4. Le résultat est évalué sur une période ultérieure.
5. L’expérience terminée peut alimenter la mémoire.

Aucun agent ne doit recevoir le résultat futur avant sa décision.

Le simulateur ne doit pas communiquer directement son étiquette de marché aux agents.

5. Indicateurs de performance

Pour chaque agent et pour le collectif :

• Taux de décisions correctes.
• Résultat net après coûts.
• Espérance par transaction.
• Drawdown maximal.
• Nombre de pertes consécutives.
• Qualité des niveaux de protection.
• Fréquence des abstentions.
• Capacité à reconnaître les situations incertaines.
• Stabilité entre différents environnements.

6. Comparaisons

Les résultats seront comparés à plusieurs références :

• Agent individuel.
• Décision collective.
• Stratégie aléatoire.
• Stratégie passive de référence.
• Absence de transaction.

7. Gouvernance

Le gestionnaire du risque conserve son droit de veto.

Un seul décideur peut autoriser une transaction.

Toute autorisation doit être vérifiée.

Aucun agent ne peut contourner les contrôles.

8. Progression

Phase A : simulations autonomes.

Phase B : tests de résistance.

Phase C : évaluation sur données historiques non utilisées pour le développement.

Phase D : connexion au compte démo Vantage, après validation des étapes précédentes.

Phase E : observation prolongée et analyse des résultats.

Aucune connexion à un compte réel ni exécution réelle n’est autorisée par ce protocole.

9. Principe directeur

CDI-TRADER doit démontrer ses capacités propres.

L’objectif n’est pas de reproduire les décisions de son créateur, mais d’évaluer objectivement la capacité des agents à analyser, décider, coopérer, reconnaître leurs erreurs et respecter leurs limites.
